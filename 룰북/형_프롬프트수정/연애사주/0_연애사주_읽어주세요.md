# 형에게 — 연애사주(hongsil) 프롬프트 수정 패키지

연애사주(나의 홍실, 1인 솔로 본인 풀이)는 **6챕터 프롬프트가 전부 한 파일**에 들어있음:
- **파일**: `lib/hongsil/prompts/v5-report.ts` (약 290줄)
- 그 안에 `buildHongsilChapter1PromptV5` ~ `buildHongsilChapter6PromptV5` 6개 함수 + 공용 함수 3개
- 형이 이 파일 직접 열어서 편집 → 저장 → 재우에게 돌려줌 → 재우가 교체

> ⚠️ `lib/hongsil/prompts/ch1-charm.ts` 같은 옛 파일들이 있는데 **그건 V2 잔재, 안 쓰임**. 진짜 동작은 `v5-report.ts` 뿐. `refinement/` 폴더(solo-escape 등)도 현재 **미연결**.

## ⛔ 절대 건드리지 말 것

### 1. `${...}` 변수 — 그대로 보존
각 챕터 함수는 JS 템플릿 리터럴(백틱)을 반환. 변수:
- `${c.name}` — 사용자 이름
- `${c.meCharacter}` — 본인 캐릭터 (옥순 등) / `${c.destinyCharacter}` — 운명 짝꿍 캐릭터
- `${buildHongsilChoiceContext(choice)}` — Q1 솔로기간·Q2 원하는 사랑·Q3 스타일 선택 컨텍스트
- `${dataBlock(c)}` — 사주 데이터 블록 자동 주입
- `${v5Principles(String(c.name))}` — V5 공용 원칙 자동 주입
- `${finalCheck(String(c.name))}` — 출력 직전 체크 자동 주입
- ch4의 `${isNever ? \`...\` : \`...\`}` — Q1이 "모태솔로(never)"면 다른 소제목. **삼항 통째 보존**.

### 2. 헤더 줄 — 한 글자도 변경 금지
- `## N장 — ...` (챕터 헤더)
- `### 소제목` — 클라이언트 매핑 키. `[페이지 타입: ...]` 줄은 헤더 아님(수정 가능).

### 3. 백틱 이스케이프
템플릿 리터럴 안. 본문에 백틱 literal 쓰려면 `\``. `[[ ]]` 강조는 백틱 아님 — 그냥 써도 됨.

### 4. 공용 함수 3개 — 영향 범위 주의
- `dataBlock(c)` — 데이터 주입 포맷. 거의 손댈 일 없음.
- `v5Principles(name)` — **6챕터 전부에 적용되는 공용 출력 원칙 1~7** (아래). 한 줄 바꾸면 전 챕터 영향.
- `finalCheck(name)` — 출력 직전 체크리스트. 6챕터 공용.
- 소제목 하나 톤만 → 그 `###` 블록만. 전 챕터 톤·형식 → `v5Principles`.

## 📐 `v5Principles` — 6챕터 공용 출력 원칙 1~7 (수정하면 전 챕터 영향)

```text
1. 근거 제시 공식 — "감각적 결론 → 한문 섞인 사주 근거 → 자리 설명 → 쉬운 번역 → 연애 장면 → 이면" 순서. 사주 근거 한 번에 2~4개만.
2. 전문용어 노출 단계 — ch1 "내 매력은?"=근거 풀 노출 / ch1 나머지·ch2~3 첫 본문=한문 1~2개 제한 허용 / ch4~6=전문용어 직접 노출 회피, 생활어로. 한자 썼으면 같은 문단에 초보자용 해석 필수.
3. 초보자 친절함 — 어려운 단어는 같은 문장/다음 문장에 쉬운 뜻. 자리(일간·일지·월지·배우자궁) 뜻 풀어줌. 용어보다 설명이 길어야.
4. 중복 회피 — 같은 근거 반복해도 같은 결론 반복 X. "내 매력은?" 이후 이미 나온 한문 병기·사주근거명 재호출 금지(파트 달라도). 각 소제목은 "아직 안 쓴 새 근거"만.
5. 문장 품질 — "~에요" 어미 기본, "~입니다" 금지. "다만" 남발 금지. 동물 비유 금지. 과한 자연 비유 금지 — 실제 말투·연락·약속·관계 장면.
6. 개인화 — ${name}님 호칭 정확히, 단독 이름 금지. 일반론 금지. 선택지 답변은 자연스럽게 맞을 때만 반영.
7. 형식 — ### 소제목 한 글자도 변경 금지. 각 소제목 5~6단락 430~680자. 강조는 [[짧은 핵심어]]만 소제목당 1~2회.
```
