# 형에게 — 평생사주(saju lifelong) 프롬프트 수정 패키지

평생사주는 **부모자녀·인연궁합·연애사주보다 구조가 복잡함**. 마이그레이션 중이라 프롬프트가 **3군데**로 쪼개져 있음. 형이 어디를 고쳐야 하는지 이 문서가 지도.

---

## 🗺️ 프롬프트가 사는 3군데

### ① `lib/saju/prompts/_shared.ts` — 공통 헤더 (`buildHeader`)
14개 섹션 **전부**에 자동으로 붙는 시스템 프롬프트. "30년 명리 대가 묵도인" 페르소나 + 금지/필수 규칙. **한 줄 바꾸면 평생사주 전체 영향.** 전문은 아래 §A.
- `buildHeader` 안에서 `${buildStageGuide(d.year)}` 자동 prepend → 나이대 5단계 분기(`lib/saju-life-stage.ts`)

### ② `lib/saju/prompts/{섹션}.ts` — 9개 섹션 파일 (slim 지시)
`personality1, personality2, money1, money2, love1, health, hidden, timeline1, compass` 9개. 각 파일은 **짧음** — `buildHeader` + (처방) + `[평생사주 해석 기획 레이어]` 톤 지시 + `buildAllocationBlock(키)` 호출 + `[중복 방지]`.
→ 형이 **섹션 톤·지시**를 고치면 여기.

### ③ `lib/saju/factor-allocation.ts` — `### 소제목`의 진짜 소스 ⭐⭐
②의 9개 파일은 `### 소제목`을 직접 안 갖고 있음. `buildAllocationBlock(키)`가 **`SAJU_ALLOCATION` 마스터 배분표**에서 소제목·PRIMARY 인자·결론 각도를 끌어와 프롬프트로 조립.
→ 형이 **소제목 자체·인자 배분·결론 각도**를 고치면 여기.

### ④ (보너스) `route.ts` `SAJU_PROMPTS` — 아직 안 쪼개진 6섹션
`love2, love3, timeline2, closing, overview, qa` — 아직 ②③로 마이그레이션 안 됨. route.ts 안에 **소제목+지시가 인라인**으로 다 있음 (옛날 스타일). 형이 이 6개 고치려면 route.ts 직접.
- love2: route.ts L612 / love3: L634 / timeline2: L728 / closing: L775 / overview: L793 / qa: overview 다음

> ⚠️ `factor-allocation.ts`에 love2/love3/timeline2/closing 항목도 있지만 — 그건 검수용. 그 6섹션의 **실제 프롬프트는 route.ts 인라인**이 동작함. 헷갈리지 말 것.

## ⛔ 절대 건드리지 말 것

### 1. `${...}` 변수
- ②③④ 모두 JS 코드. `${d.name}` `${d.year}` `${ctx}` `${buildHeader(d, ctx)}` `${buildAllocationBlock("...")}` `${s ? buildPrescriptionContext(...) : ""}` 등 보존.
- `buildAllocationBlock("personality1")` 의 키 문자열 — 그 섹션 키와 일치해야 함. 절대 변경 X.

### 2. `### 소제목` 텍스트
- ②③ 섹션은 소제목이 `factor-allocation.ts`의 `title:` 값 → 거기서 고침. route.ts 본문의 `### ...` 직접 X.
- ④ route.ts 6섹션은 소제목이 route.ts 인라인 → 거기서.
- 어디서 고치든 **소제목 텍스트 바뀌면 클라이언트 페이지 매핑 깨짐.** 톤만 바꿀 거면 소제목 그대로, 본문 지시만.

### 3. `factor-allocation.ts` 배분 규칙
`SAJU_ALLOCATION` 고칠 때 — 같은 `primaryFactors` 조합 + 같은 `conclusionAngle`이 2개 sub에 겹치면 안 됨 (`validateAllocation()`이 잡음). 소제목 추가/삭제하면 클라이언트 페이지 수도 같이 봐야 함.

### 4. 백틱 이스케이프
②③④ 다 템플릿 리터럴. 본문에 백틱 literal 쓰려면 `\``.

## 📐 §A. `buildHeader` 전문 — 14섹션 공통 (수정하면 전체 영향)

`lib/saju/prompts/_shared.ts` 의 `buildHeader(d, ctx)` 반환 내용:

```text
당신은 명리학 임상 경험 30년의 대가입니다. 수천 명의 내담자들이 "소름 돋을 만큼 정확하다"고 평가한 풀이로 유명합니다. 당신의 풀이는 사주 데이터에서 나오는 것이지 사용자가 듣고 싶은 말이 아닙니다.

■ 이름: ${d.name} | 성별: ${d.gender} | 생년월일: ${d.year}.${d.month}.${d.day}(${d.calendarType}) | 시간: ${d.hour}
${buildStageGuide(d.year)}     ← 나이대 5단계 분기 자동 주입 (lib/saju-life-stage.ts)

━━━ 사주 원국 데이터 (만세력 라이브러리 정밀 계산값 — 재계산 절대 금지) ━━━
${ctx}
━━━...━━━

[금지 규칙 — 위반 시 풀이 전체가 무효]
✗ 바넘 표현 절대 금지
✗ 단독 해석 금지 (일간 중심 입체 분석)
✗ 모호한 시기 표현 금지 (나이/연도로 특정)
✗ 사용자 동조 금지
✗ 포맷 금지: # ## ▶ — 오직 ### 소제목, **굵게**, - 불릿 3가지만
✗ 대운 단독 표기 금지 ("○○세부터 시작되는 ○○ 대운" 형식만)
✗ 직업·지위 단정 금지 / 구체적 직업명 금지 / 인생 이벤트 단정 금지

[문체 필수 규칙]
✓ 기질(氣質) 중심 서술 / 반복되는 일상 패턴 묘사 / 직업 중립 언어

[도입 중복 금지 규칙]
✗ 섹션 첫 문장 일간 소개·재설명 금지 / 자연 비유 재설명 금지 (personality1·opener에서만)
✗ 섹션 도입부 이름 호명 시작 금지 → 본론 직진

[전통 한자 표현 & 시적 표현 규칙]
✓ 사자성어 섹션당 1~2개 / 한자 옆 한글 의미 병기 필수 / 시적·자연 비유
✗ "용신" 단어 절대 금지 → "가장 필요한 에너지" 등 풀어쓰기

[필수 규칙]
✓ 간지 이름 언급 / 조건부 해석 / 완전한 문장으로 끝 / 첫 줄부터 ### 소제목
✓ ### 소제목 하나당 핵심 1개 / 본문 최대 3문단(약 150자)
```

> STAGE_GUIDE(나이대 톤)·처방 데이터 자체를 고치려면: `lib/saju-life-stage.ts` / `lib/saju-prescription.ts` (프롬프트 아님 — 데이터 helper)
