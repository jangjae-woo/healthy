# 형에게 — 인연궁합(inyeon) 프롬프트 수정 패키지

인연궁합은 부모자녀와 **구조가 다름**. 부모자녀는 route.ts 한 덩어리라 내가 본문을 메모에 떠다 줬지만, 인연궁합은 **이미 챕터별 독립 파일**이야. 그래서 이 패키지는 "파일 떠다 주기"가 아니라 **"형이 직접 열어서 고칠 파일 + 주의사항 가이드"**.

- 프롬프트 파일 위치: `lib/inyeon/prompts/ch1-basic.ts` ~ `ch8-final-letter.ts` (8개)
- 형이 그 파일을 직접 열어서 편집 → 저장 → 재우에게 파일째 돌려줌 → 재우가 파일 교체

---

## ⛔ 절대 건드리지 말 것

### 1. `${...}` 변수 — 그대로 보존
모든 챕터 파일은 `export function buildInyeonChapterNPrompt(...)` 가 **JS 템플릿 리터럴**(백틱)을 반환하는 구조. 안에 변수가 빽빽함:
- `${c.aName}`, `${c.bName}` — 두 사람 이름 (또는 `${a.name}`, `${b.name}`)
- `${c.aIlgan}`, `${c.ilganRelation}`, `${c.aOhaengTop}` 등 — 사주 데이터
- `${choiceCtx}` — 관계·기간 선택 컨텍스트
- `${INYEON_V2_PRINCIPLES(...)}`, `${INYEON_V2_END_CHECK(...)}` — 공통 원칙 자동 주입
- `${plan.sectionTitle}`, `${subsBlock}`, `${bonneungSection}` — 관계 분기로 조립된 값
- `${c.aCharacter ? \`...\` : ""}` — 조건부 블록 (캐릭터 있을 때만)

→ 변수·삼항·조건부 전부 그대로. **형이 고치는 건 본문 텍스트(소제목 스펙)뿐.**

### 2. 헤더 줄 — 한 글자도 변경 금지
- `## 챕터 제목` / `### 소제목`
- 출력 룰 안의 `\`### 소제목\`` (백틱 이스케이프된 것)

클라이언트가 챕터 인덱스 + `### sub`로 본문을 매핑함. 헤더 텍스트 바뀌면 그 sub가 화면에서 깨짐.

### 3. ⭐ ch5·ch6·ch7 — 소제목이 "이중 따옴표 JS 문자열" 안에 있음 (제일 위험)
ch1~ch4, ch8은 `### 소제목` 블록이 백틱 템플릿 리터럴 안에 **그냥 텍스트**로 있어서 편하게 고침.

**하지만 ch5·ch6·ch7은 다름.** 소제목 블록이 `const ...BY_RELATIONSHIP` 레코드 안의 **큰따옴표 JS 문자열**로 들어있음:
```ts
guide: "[메인: ...]\n[시그너처: ...]\n구성: ① 단정 한 줄 — \"두 분은...\" → ② ..."
```
- 줄바꿈은 진짜 줄바꿈이 아니라 `\n` 글자
- 본문 안 따옴표는 `\"` 로 이스케이프
- `__A__`, `__B__` 는 나중에 이름으로 치환되는 placeholder — 그대로 둘 것
- `__MARRIAGE_YEAR__` 등(ch7)도 placeholder

→ ch5·6·7 고칠 땐 **`\n`·`\"`·`__A__` 보존**. 줄바꿈 넣고 싶으면 `\n`으로, 따옴표는 `\"`로. 안 그러면 문자열이 터짐.

### 4. 공통 원칙 vs 챕터 스펙 — 충돌 금지
모든 챕터가 `INYEON_V2_PRINCIPLES` (A~N, 아래 참조)를 자동 주입받음. 챕터 본문 스펙은 이 원칙 안에서 움직여야 함. 공통 원칙 자체를 바꾸려면 `lib/inyeon/prompts/v2-principles.ts`.

## 📐 모든 챕터 공통 [INYEON_V2_PRINCIPLES A~N] — 참고용 (수정 대상 아님)

`lib/inyeon/prompts/v2-principles.ts` 에 있음. 형이 챕터 본문 고칠 때 이 톤 안에서:

```text
A. 사주 용어 노출 — 메인 인자 한자병기 1회만. 격국명 금지. 신살명 한자병기 1회 허용.
B. 글 모양 다양화 — 모든 sub 동일 산문체 템플릿 금지. 첫 문장·단락 리듬·장면 소재가 서로 달라야.
C. 첫 줄 cadence 풀 — 한 챕터 안 같은 cadence 두 번 금지. 6종: 캐치프레이즈 단정 / 질문 던지기 / 한 컷 묘사 시작 / 자연 비유 시작 / 시간 묘사 / 양방향 도입. (양방향 분리 묘사 sub은 6번 의무)
D. 깊이와 개인화 — 결론만 X. 메인+서브 인자 2~3개 연결. 단일 인자 풀이 금지. 일반론 금지.
E. 십성·오행 강도 분기 — 강:두드러지는 결 / 중:양면 / 약:옅은 결+다른 결이 채움 / 0:양면 풀이 강제. "약해서 보완" 금지.
F. 두 분 어조 보호 — "맞지 않는/문제 있는/약한 인연" 금지. 한쪽 비하 절대 X.
G. 이름 고정 — 입력값 그대로. 변형·중복 글자·별칭 금지.
H. 두 분 호명 다양성 — "두 분"/"○○님과 △△님"/"이 두 결" 다양화.
I. 사건 확정·정량 금지 — 점수·% 직접 인용 X. "운명적/반드시/평생" 확정 X. 가능성 어조.
J. 마크다운 헤더 정확 출력 — 헤더 텍스트 한 자도 변경 금지.
K. 관계 분기 톤 충실 — 짝사랑/썸/연인초기/연인안정기/부부/재회 6 관계 톤 혼용 금지.
L. 가독성 강조 — 별표·물결·백틱·이모지 금지. [[텍스트]] 1종만, sub당 1~2회, 10자 이내.
M. 모든 문장 "~에요" 어미 — "~입니다" 금지.
N. 본능궁합 sub 톤 (5장 한정) — 노골 묘사·19+ 절대 금지. 결·기운·온도·리듬 자연 비유.
```

## 🔄 작업 흐름
1. 재우가 형한테 이 폴더(또는 특정 챕터 메모 + 해당 .ts 파일)를 줌
2. 형이 `.ts` 파일 열어서 본문 스펙만 수정 (변수·헤더·`\n`·`\"`·`__A__` 보존)
3. 형이 수정한 `.ts` 파일 돌려줌
4. 재우가 파일 교체
5. 배포 → `node saju_test.js inyeon preset1` 회귀 확인
