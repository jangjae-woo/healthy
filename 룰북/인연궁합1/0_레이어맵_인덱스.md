# 인연궁합 (紅蓮) — 6 레이어 인덱스

```
입력 (a + b 사주 + 6 관계 분기 + 6 만남 기간)
   ↓
1. 엔진 레이어              → 두 사람 사주 원국·궁합 점수·체질·시기·본능 결합 계산
   ↓
2. 해석 기획 레이어         → 8 챕터별 인자 분배·중복 방지·홍연 톤·관계 분기 시그너처
   ↓
3. 캐릭터 매핑 레이어        → 홍도인(紅道人) narrator + 12 캐릭터 풀(여6·남6) + 36 페어 매트릭스
   ↓
5. LLM 생성 레이어 (Gemini) → 챕터별 prompt → 본문 스트리밍 (단일 fetch, 8 챕터 순차)
   ↓
4. LLM 검수팀               → 결정론 가드 → judge → rewrite → 결정론 가드 (이중)
   ↓
6. 렌더 레이어              → SSE 누적 → ### sub 헤더 분리 → ChSub 표시
   ↓
결과 (8 챕터 풀이지)
```

## 작업 시 수정 범위 가이드
| 수정하고 싶은 것 | 손대야 할 레이어 |
|---|---|
| 사주 계산법 변경 | 1 (다른 서비스 영향 검토) |
| 챕터별 톤 / 중복 정책 | 2 |
| 관계 분기 로직 (crush/dating/married 등) | 2 (sub-distribution.ts) + 5 (ch{N}-*.ts 관계별) |
| 캐릭터 매핑 / 페어 라벨 | 3 |
| 본문 생성 prompt | 5 (ch{N}-*.ts) |
| 본문 검수 / 자동 보정 | 4 (llm-output-guard.ts inyeon 분기) |
| 결과 화면 디자인 / 시각자료 | 6 |
| 환각·결핍·반복 같은 출력 결함 | 4 (가드) — 5의 prompt 룰로는 한계 |

## 6 관계 분기
- `crush` — 짝사랑
- `talking` — 썸·소개팅
- `dating_short` — 연인 (3개월 미만)
- `dating_long` — 연인 (3개월 이상)
- `married` — 부부
- `exboyfriend` — 재회·헤어진 사람

→ 5장(깊은 결)·6장(필요한 것)·7장(결혼·미래)·8장(편지)는 **관계별 섹션 제목까지 다름**. 챕터 정체성이 관계별 분기.

## 6 만남 기간 (duration)
- `lt_1m` (1개월 미만) / `1to3m` / `3to6m` / `6mto1y` / `1to3y` / `gt_3y`
→ EntryModal에서 관계+기간 선택, shared-context.ts의 `relationshipTone()`·`stageGuide()`가 LLM prompt에 자동 주입.

- 90%+ 가려면 의미 충돌 검수룰 강화 + 관계별 매핑 helper 추가
