# 아이기질과 부모양육 위키 인수인계

작성일: 2026-05-18

## 현재 결론

아이기질 보고서는 전체를 LLM으로 다시 만들지 않는다. 기존 팔자원 렌더와 페이지 구조는 유지하고, LLM이 담당해야 하는 문장 블록만 분리한다.

핵심 구조:

```text
기존 렌더/계산값/표/차트는 그대로 사용
Claude Code는 사용자가 지정한 문장 블록만 생성
부모+아이 조합 전체를 전수 캐시하지 않음
단독 블록은 캐시 가능
아이+부모 조합부는 결제 시점 LLM 생성 후 캐시 저장
```

## 왜 이 구조로 바꿨는가

처음에는 아이+어머님+아버님 완성 리포트를 전부 미리 생성하는 방향을 검토했다. 하지만 조합 수가 너무 크다.

아이 범위:

```text
아이 출생일: 2020~2023년 = 1,461일
시간 옵션: 12지지 + 시간모름 = 13개
성별: 남/여 = 2개

아이 단독 경우의 수:
1,461 × 13 × 2 = 37,986개
```

아이 단독 캐시는 가능하다.

부모까지 붙이면:

```text
부모 출생 범위 예시: 1970~2005년
부모 출생일: 13,149일
부모 시간 옵션: 13개
부모 1명 경우의 수: 170,937개

아이 + 부모 1명:
37,986 × 170,937 = 6,493,212,882개

아이+어머님 + 아이+아버님:
약 12,986,425,764개
```

즉 약 129.8억 조합이다. 텍스트를 1개당 1KB로만 잡아도 약 12.8TB이고, 실제 JSON/본문 기준으로는 수십~수백 TB가 된다. 따라서 아이+부모 조합 전수 저장은 현실적이지 않다.

## 최종 저장 전략

```text
1. 기존 렌더는 유지
2. 단독으로 가능한 문장 블록은 미리 캐시
3. 아이+부모 조합이 필요한 블록만 결제 시점에 LLM 생성
4. 생성된 pair 결과는 재사용을 위해 캐시
```

권장 저장 구조:

```text
youa/v1/standalone/child/{childKey}.json
youa/v1/standalone/parent/{parentKey}.json
youa/v1/pair/{childKey}_{parentKey}.json
youa/v1/final/{childKey}_{motherKey}_{fatherKey}.json
```

단, 현재 단계에서는 저장소 구현보다 먼저 기존 샘플을 블록 구조로 쪼개는 검증이 우선이다.

## 페이지별 처리 방식

### 기존 그대로 사용

```text
1~3페이지: 기존 그대로
10~12페이지: 기존 그대로
레이아웃, 차트, 점수바, 사주 원국표, 6가지 기운 카드: 기존 그대로
```

### 4~9페이지: 아이 6요인 페이지

대상:

```text
4페이지 활기
5페이지 조심
6페이지 만족
7페이지 흔들림
8페이지 어울림
9페이지 끈기
```

Claude Code가 생성/캐시할 블록:

```text
whyIntro
dailyBody
parentingTipTime
parentingTipCommunication
parentingTipEnvironment
```

기존 계산/렌더로 유지:

```text
장 제목
요인명
점수 바
점수/등급
score-box 기본 문장
사주 인자 표
```

삭제/LLM 생성 제외:

```text
사주 인자 표 아래의 긴 종합 설명 블록
```

### 13~14페이지: 부모 단독 사주

13페이지 어머님, 14페이지 아버님.

Claude Code가 생성/캐시할 블록:

```text
parentSajuBody
parentSajuBridge
```

기존 계산/렌더로 유지:

```text
장 제목
사주 원국표
일간/일주/강한 기운 요약
6가지 기운 카드
```

### 15페이지: 부모-자녀 사주 궁합

Claude Code가 결제 시점에 생성할 pair-generation 블록:

```text
motherChildCompatibility
fatherChildCompatibility
parentPalaceSummary
```

이 영역은 아이+어머님, 아이+아버님 2인 조합이다. 아이+어머님+아버님 3인 전체 전수 생성은 하지 않는다.

### 16페이지: 함께 살펴줄 결

Claude Code가 결제 시점에 생성할 pair-generation 블록:

```text
motherSynergyBody
motherSynergyDaily
motherConflictBody
motherConflictDaily
motherConflictResolution
fatherSynergyBody
fatherSynergyDaily
fatherConflictBody
fatherConflictDaily
fatherConflictResolution
```

규칙:

```text
시너지 카드에는 "이렇게 풀어보세요"를 넣지 않는다.
충돌 카드에만 "이렇게 풀어보세요"를 넣는다.
```

## Claude Code에게 넘길 정확한 지시문

아래 문장을 그대로 전달하면 된다.

```text
현재 작업 목표를 다시 정리한다.

기존 팔자원 아이기질 보고서의 렌더/페이지 구조는 그대로 유지한다.
전체 보고서를 새로 만들거나 전체 페이지를 캐시화하지 않는다.

Claude Code가 다룰 것은 LLM 문장 블록뿐이다.

단독 캐시 블록은 다음이다.

A. 4~9페이지 6요인 페이지별 블록
각 요인별로 아래 5개만 분리한다.
- whyIntro: "왜 이런 결인가" 아래의 짧은 도입 문단
- dailyBody: "일상에서는..." 본문
- parentingTipTime: 양육 Tip 중 시간 관련 팁
- parentingTipCommunication: 양육 Tip 중 소통 관련 팁
- parentingTipEnvironment: 양육 Tip 중 환경 관련 팁

대상 요인:
활기, 조심, 만족, 흔들림, 어울림, 끈기

B. 13~14페이지 부모 단독 사주 블록
어머님/아버님 각각 아래 2개만 분리한다.
- parentSajuBody: 부모 사주를 설명하는 본문
- parentSajuBridge: 부모의 결이 아이의 결과 만나는 자리는 뒤에서 정리된다는 연결 문장

pair-generation 조합 블록은 다음이다.

C. 15페이지 부모-자녀 사주 궁합 블록
- motherChildCompatibility: 어머님과 아이의 사주 궁합 본문
- fatherChildCompatibility: 아버님과 아이의 사주 궁합 본문
- parentPalaceSummary: 아이 사주 안에서 본 어머님/아버님 자리 또는 일지 관계 설명

D. 16페이지 함께 살펴줄 결 블록
- motherSynergyBody
- motherSynergyDaily
- motherConflictBody
- motherConflictDaily
- motherConflictResolution
- fatherSynergyBody
- fatherSynergyDaily
- fatherConflictBody
- fatherConflictDaily
- fatherConflictResolution

지금은 새로 대량 생성하지 말고,
기존 output/sample-001.json ~ sample-004.json 4개에서 위 블록에 해당하는 내용만 분리해라.

분리 결과는 아래처럼 만든다.

output-blocks/

  sample-002/

  sample-003/
    standalone-blocks.json

    pair-generation-output.json
    block-manifest.json

  sample-004/
    standalone-blocks.json
    pair-generation-input.json
    pair-generation-output.json
    block-manifest.json

먼저 파일 만들지 말고,
네가 이해한 블록 분리 구조를 요약해서 답해라.
```

## 평생사주에 적용할 때의 방향

사용자가 다음에 하려는 작업은 `평생사주`에도 같은 방식 적용이다.

진행 방식:

```text
1. 평생사주 index URL 또는 기준 HTML을 보여준다.
2. 기존 렌더/고정 페이지/계산값 영역을 먼저 구분한다.
3. LLM이 실제로 써야 하는 문장 블록만 사용자와 함께 페이지별로 지정한다.
4. 지정된 블록만 단독 캐시/조합 생성/pair-generation으로 나눈다.
5. 전체 완성 리포트 전수 생성이 아니라, 현실적인 캐시 단위로 분리한다.
```

주의:

```text
처음부터 Codex가 임의로 스키마를 쪼개면 안 된다.
사용자가 페이지와 블록을 직접 지정한다.
Codex는 사용자가 지정한 블록을 이름 있는 필드로 바꿔서 Claude Code나 다른 생성기에 전달한다.
```
