# 사주로 풀어보는 우리 아이 마음 - 대량 생성 지침서 v1

이 문서는 `index.html` 샘플을 그대로 복사하기 위한 문서가 아니다. 실제 고객이 LLM을 돌렸을 때 받을 법한 보고서를 미리 대량 생성해 Cloudflare R2에 저장하기 위한 생성 지침서다.

목표는 다음 3가지를 동시에 만족하는 것이다.

1. 사주 계산값은 코드가 결정한다.
2. 본문은 형 버전의 문체와 구조를 유지한다.
3. Claude Code는 정해진 변수와 규칙 안에서 다양한 조합의 보고서 본문을 대량 생성한다.

## 1. 전체 구조

생성 파이프라인은 다음 순서로 고정한다.

```text
입력 생년월일시/성별/부모 정보
→ 사주 계산 엔진
→ 6요인 점수와 5단계 등급 산출
→ 사주 인자/카운트/관계 변수 산출
→ Claude Code 대량 생성 프롬프트 투입
→ JSON 결과 생성
→ validator 검사
→ Cloudflare R2 저장
→ 팔자원 사이트에서 조회 후 렌더링
```

Claude Code가 직접 만들어도 되는 것은 문장 조합과 설명 문맥이다. Claude Code가 임의로 만들면 안 되는 것은 점수, 등급, 사주 인자, 이름, 위치, 카운트, 생극합 관계다.

## 2. 5단계 등급

기존 A.txt는 `낮음/중간/높음` 3단계 기준이다. 실제 서비스에서는 다음 5단계를 사용한다.

| 점수 | 등급 | 설명 방향 |
|---:|---|---|
| 0-20 | 매우낮음 | 해당 결이 아주 약하거나 반대 결이 강하게 작동 |
| 21-40 | 낮음 | 해당 결이 은은하고 반대 결이 더 잘 드러남 |
| 41-60 | 중간 | 양쪽 결이 함께 있고 상황에 따라 달라짐 |
| 61-80 | 높음 | 해당 결이 분명하게 드러남 |
| 81-100 | 매우높음 | 해당 결이 매우 강하고 일상 전반에 깊게 작동 |

중요한 규칙:

- `28점 = 낮음`, `70점 = 높음`이어야 한다.
- 등급 라벨과 본문 톤이 반드시 일치해야 한다.
- 5단계 등급은 표시용만이 아니라 일상 사례, 양육팁, 동물 유형, 부모-자녀 매트릭스에도 반영한다.
- 시간 모름 케이스에서는 시주 관련 인자를 제외하고, 없음 패널티를 주지 않는다.
- 시간 있음/없음 차이는 전체 점수 기준 최대 5점 안에서 흔들리게 보정한다.

## 3. 생성 단위

완성 보고서는 아래 12장 구조를 따른다.

| 장 | 생성 영역 | 대량 생성 여부 |
|---:|---|---|
| 1장 | 보고서 안내 | 고정 템플릿 + 이름 변수 |
| 2장 | 아이기질 한눈에 보기 | 점수/등급/차트 변수 |
| 3장 | 활기 | 요인별 대량 생성 |
| 4장 | 조심 | 요인별 대량 생성 |
| 5장 | 만족 | 요인별 대량 생성 |
| 6장 | 흔들림 | 요인별 대량 생성 |
| 7장 | 어울림 | 요인별 대량 생성 |
| 8장 | 끈기 | 요인별 대량 생성 |
| 9장 | 어머님 사주 | 부모별 대량 생성 |
| 10장 | 아버님 사주 | 부모별 대량 생성 |
| 11장 | 부모-자녀 사주 궁합 | 관계별 대량 생성 |
| 12장 | 함께 살펴줄 결 | 매트릭스 조합별 대량 생성 |

## 4. 요인 6개

각 요인은 낮은 쪽과 높은 쪽이 모두 의미를 가진다. 낮다고 부족하다는 식으로 쓰지 않는다.

| 요인 | 낮은 쪽 | 높은 쪽 |
|---|---|---|
| 활기 | 차분함, 머무름, 회복 중심 | 움직임, 에너지, 표현 |
| 조심 | 적극성, 접근성, 대담함 | 신중함, 안전 탐색, 수줍음 |
| 만족 | 까다로운 감각, 쉽게 만족하지 않음 | 낙관, 즐거움 발견, 유쾌함 |
| 흔들림 | 정서 안정, 회복 빠름 | 민감함, 깊은 감정, 회복 시간 |
| 어울림 | 독립성, 혼자만의 편안함 | 공감, 사교성, 관계 민감성 |
| 끈기 | 관심 이동, 유연함, 즉흥성 | 인내, 지속성, 끝까지 붙잡음 |

## 5. 요인별 본문 구조

요인별 장은 반드시 같은 골격을 가진다.

### 5.1 결 한눈에 박스

필수 입력:

```json
{
  "factor": "활기",
  "score": 70,
  "level": "높음",
  "childName": "김수민 양"
}
```

출력 구조:

```text
{childName}의 {factor}은 {score}점, {level} 결입니다.
{factorLevelSummary}
```

`factorLevelSummary`는 6요인 x 5등급별로 별도 문장 풀을 둔다.

### 5.2 왜 이런 결인가

도입은 짧게 고정한다.

```text
{childName}의 {factor} {score}점은 사주에서 {factor}을 만드는 기운과 누르는 기운이 함께 결합되어 나온 결과입니다.
```

그 다음은 코드가 산출한 만드는 기운/누르는 기운 표를 넣는다.

```json
{
  "makers": [
    {
      "label": "표현하는 기운",
      "raw": "식신",
      "position": "월지",
      "strength": "strong"
    }
  ],
  "suppressors": [
    {
      "label": "절제하는 기운",
      "raw": "정관",
      "position": "시주",
      "strength": "weak"
    }
  ]
}
```

종합 산문은 반드시 다음 흐름을 따른다.

```text
1문단: 만드는 기운과 누르는 기운의 구성 비교
2문단: 어떤 쪽이 더 우세한지와 그래서 점수가 왜 그 등급인지 설명
```

Claude Code는 인자를 새로 만들지 않는다. 전달받은 `makers`, `suppressors`, `makerCount`, `suppressorCount`, `dominantSide`만 사용한다.

### 5.3 일상에서는

형 버전처럼 2-3문장으로 풍부하게 쓴다. 단순 설명이 아니라 구체 장면이 있어야 한다.

필수 구성:

```text
1문장: 장소/상황/물건/행동
2문장: 시간대나 반복되는 생활 장면
3문장: 또래와 비교했을 때 드러나는 방식
```

금지:

- "{factor}이 높아서 {factor}이 높습니다" 같은 반복
- 너무 추상적인 조언
- 모든 요인이 같은 문장 구조로 보이는 복붙 느낌

### 5.4 양육 Tip

항상 3축으로 쓴다.

```text
시간
소통
환경
```

각 축은 제목 1개와 본문 2-3문장으로 구성한다. 본문 안에는 가능하면 사주 인자 또는 결의 원리를 1회 이상 반영한다.

## 6. 부모 사주 생성 규칙

부모 사주는 400자 이하를 원칙으로 한다. 다만 빈약하게 1-2줄로 끝내지 않는다.

필수 구조:

```text
1문단: 일간 소개
2문단: 일간 비유의 성향 설명
3문단: 사주에서 강한 기운 2-3개와 조후 흐름
```

일간은 한자를 그대로 던지지 않고 풀이한다.

예:

```text
정화(丁)는 촛불·작은 등불처럼 안에서 따스하게 비추는 작은 불의 기운입니다.
경금(庚)은 도끼·큰 칼처럼 기준을 세우고 필요할 때 단단하게 잘라내는 큰 쇠의 기운입니다.
```

## 7. 부모-자녀 궁합 생성 규칙

궁합은 반드시 다음 순서로 쓴다.

```text
1. 두 사람의 일간 비유
2. 생/극/합/동기/설기 등 실제 관계 설명
3. 일상에서 보이는 장면
4. 양방향 영향
```

주의:

- 관계명은 코드가 산출한 값을 사용한다.
- 무조건 `생/극`만 쓰지 않는다.
- 천간합이 있으면 천간합을 우선 설명한다.
- `인성`, `재성` 같은 내부 용어만 노출하지 말고 `받쳐주는 흐름`, `결과를 기대하는 흐름`처럼 풀어 쓴다.

## 8. 함께 살펴줄 결 - 매트릭스 카드

매트릭스 카드는 시너지와 충돌을 구분한다.

시너지 카드:

```text
헤더: 아이가 어떤 상황일 때 부모 결이 어떻게 돕는지
서브: {강도} 시너지 - {부모기운명}({부모점수}) x {자녀결명}({자녀점수})
본문1: 부모 결 설명
본문2: 자녀 결 설명
본문3: 두 결이 만나 생기는 흐름
일상 사례: 2개 bullet
```

충돌 카드:

```text
헤더: 부모 결이 아이 결을 어떻게 위축/자극할 수 있는지
서브: {강도} 충돌 - {부모기운명}({부모점수}) x {자녀결명}({자녀점수})
본문1: 부모 결 설명
본문2: 자녀 결 설명
본문3: 충돌 메커니즘
일상 사례: 1-2개 bullet
이렇게 풀어보세요: 충돌 카드에만 표시
```

`이렇게 풀어보세요`는 강한 시너지에는 넣지 않는다.

## 9. 동물 유형 생성 규칙

동물 유형은 단순 최고점 1개만 보지 않는다.

입력:

```json
{
  "animal": "양",
  "primaryFactor": "흔들림",
  "topFactors": [
    { "factor": "어울림", "score": 78 },
    { "factor": "흔들림", "score": 75 },
    { "factor": "조심", "score": 72 }
  ],
  "matchCase": "B"
}
```

분기:

```text
A 단독: 1위 요인이 2위보다 10점 이상 높음
B 비등: 상위 2-3개가 10점 이내로 함께 깊음
C 균형: 6요인이 모두 큰 차이 없이 분포
```

시간 모름 케이스에서는 동물 유형이 쉽게 바뀌지 않게 보정한다. 시간 있음/없음으로 1위가 바뀌더라도 점수 차가 5점 이내라면 `B 비등`으로 설명하고, 확정적으로 단정하지 않는다.

## 10. 출력 원칙

Claude Code의 출력은 반드시 JSON이어야 한다. HTML 전체를 자유롭게 만들지 않는다.

금지:

- 점수 임의 생성
- 이름 임의 생성
- `undefined`, `null`, `child0`, `mother`, `father` 노출
- 등급과 점수 불일치
- 한자만 단독 노출
- 같은 문단의 앞뒤 말 반복
- 모든 요인이 같은 문장으로 보이는 템플릿 반복

허용:

- 같은 구조 사용
- 변수 치환
- 형 버전의 문체 유지
- 사주 인자에 맞는 표현 풀 선택
- 일상 사례 다양화

## 11. Cloudflare R2 저장 단위

처음부터 부모 3인 전체 조합을 하나의 파일로만 저장하면 조합 수가 폭발한다. 저장 단위는 분리한다.

권장:

```text
youa/v1/child/{childKey}.json
youa/v1/parent/{parentKey}.json
youa/v1/match/{childKey}/{parentKey}.json
youa/v1/family/{childKey}/{motherKey}/{fatherKey}.json
```

`family`는 최종 조립본 캐시다. 없으면 child + parent + match를 조합해서 만들고, 생성 후 저장한다.
