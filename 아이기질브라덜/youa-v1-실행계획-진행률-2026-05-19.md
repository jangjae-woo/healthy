# 아이기질+부모양육 v1 실행계획/진행률

작성일: 2026-05-19

## 최종 목표

정확한 사주 계산과 아이/부모 조합 판단을 기반으로, 부모가 읽었을 때 아이를 더 잘 이해하고 실제 양육에 적용할 수 있다고 느끼는 유료 아이기질+부모양육 보고서를 자동으로 안정적으로 생산하는 시스템.

평생사주와 같은 원칙을 적용한다.

```text
계산 엔진 = 사주 판단
판단표 = 어떤 결론을 낼지 고정
문장 블록/캐시 = 사람이 읽는 보고서 표현
LLM/override = 문장 품질 보정
QA = 사주 근거와 문장 모순 제거
```

## 현재 판단

아이기질+부모양육은 0%에서 시작하지 않는다.

이미 아래 자산이 존재한다.

- 아이 6요인 계산 규칙
- 부모 양육 6축 계산 규칙
- 부모-아이 궁합/매트릭스 구조
- `lib/youa-engine/youa` 계산/렌더/검증 엔진
- 아이/부모 대량 캐시
- 샘플 4개 block 분리 산출물
- 리뷰 HTML
- `/api/youa-family-report` API
- R2 업로드/조회 구조

따라서 현재 시작 진행률은 **60%**로 본다.

## 진행률 기준

| 진행률 | 상태 | 의미 |
|---:|---|---|
| 10% | 목표 확정 | 상품이 무엇인지, 누가 읽는지, 어디까지 자동화할지 정의 |
| 20% | 엔진 감사 | 아이 6요인/부모 6축/궁합 매트릭스 계산 근거 확인 |
| 35% | 상품 계약 | 페이지 구조, 필수 블록, 금지 표현, 검수 기준 고정 |
| 50% | 판단표 고정 | 아이 요인+부모 축+관계 조합의 판단표 확정 |
| 65% | 산출물 정규화 | 계산값에서 report-data/render-blocks 형태로 안정 변환 |
| 80% | 미리보기/검수 | 샘플 HTML, 형 검수 체크리스트, 문장 수정 루틴 준비 |
| 90% | 운영 준비 | R2/캐시/API/QA 스크립트 연결, 샘플 통과 |
| 100% | 판매 준비 | 형 검수 반영, 대표 샘플 통과, 유료 플로우 연결 |

현재 위치: **60%**

이유:

- 계산/렌더/캐시/API는 이미 있다.
- 샘플 4개 QA도 한 번 통과했다.
- 다만 평생사주처럼 상품 계약, 판단표 감사, override/최종 QA 체계가 아직 한 파일로 고정되지 않았다.

## 상품 구조 초안

아이기질+부모양육은 크게 4층이다.

1. 아이 단독 기질
   - 활기
   - 조심
   - 만족
   - 흔들림
   - 어울림
   - 끈기

2. 부모 단독 양육 결
   - 온기
   - 중심
   - 일관
   - 자율
   - 표현
   - 바람

3. 부모-아이 궁합
   - 엄마와 아이
   - 아빠와 아이
   - 아이 사주 안에서 보이는 부모 자리

4. 함께 살펴줄 결
   - 시너지
   - 충돌
   - 일상 적용
   - 충돌일 때만 해결 카드

## 운영 원칙

LLM은 아이나 부모의 사주를 새로 판단하지 않는다.

LLM 또는 문장 캐시가 할 수 있는 일:

- 문장을 자연스럽게 만든다.
- 부모가 읽기 편한 톤으로 바꾼다.
- 일상 예시를 붙인다.
- 과장/비난/단정 표현을 줄인다.

LLM 또는 문장 캐시가 하면 안 되는 일:

- 점수 조작
- 없는 요인 생성
- 부모/아이 관계를 단정적으로 낙인찍기
- 아이 문제를 부모 탓으로 몰기
- 질병/발달장애/심리진단처럼 말하기
- 사주 근거 없는 조언 추가
