## 기술적 결정

### D1. `manseryeok` 라이브러리 제거 → 인라인 JDN 계산
- **맥락**: 초기 `lib/saju-calculator.ts`가 `manseryeok` npm 패키지에 의존
- **옵션**: (a) 의존성 유지, (b) 인라인 구현, (c) 다른 라이브러리
- **선택**: **(b) 인라인 구현**
- **이유**: 빌드 의존성 0, 외부 패키지 변동 영향 없음, JDN(Julian Day Number) 기반으로 정확
- **구현**: 2000-01-01 = 戊午일 기준, JDN 차이로 60갑자 인덱스 계산

### D2. Next.js 14 (App Router)
- **이유**: 운영 사이트(paljawon.com)와 동일 스택, API Routes 간편
- **포트**: 3456 (운영과 충돌 방지)

### D3. Gemini API 키 — 사용자 입력 방식
- **맥락**: 서버에 키 박을지, 사용자에게 받을지
- **선택**: **사용자가 페이지에서 직접 입력**
- **이유**: 테스트 환경이라 비용 분리 + 유연성

### D4. 마크다운 렌더러 자체 구현
- **이유**: `react-markdown` 등 외부 의존 줄이고 가벼움 유지
- **지원**: `#` h1, `##` h2, `###` h3, `>` blockquote, `*`/`-` list, `**bold**`, `*italic*`, `` `code` ``

## 콘텐츠 결정

### D5. 부모-자녀 사주 = 양육 코칭 매뉴얼
- **포지셔닝**: 점쟁이 X, 발달심리학 + 사주 = 양육 매뉴얼
- **타겟**: 자녀 두신 부모 (만 0~18세)
- **차별점**: AI 해석 + 시각화 카드 + 시기별 자동 매칭

### D6. 12장 → 45p 목차 확장
- **맥락**: 처음 7섹션(연령 무관) → 12장(연령별) → 45p(세분화)
- **이유**: 분량 = 가치. 압축적 분석은 단순 텍스트로 가능하지만 **시각화 + 양육 매뉴얼 깊이** 가 차별점

### D7. PART 분리 — 엄마 + 아빠 별도 PART
- **맥락**: 처음에는 PART 4 "엄마와 우리 아이" 만 있었음
- **결정**: 아빠도 별도 PART 5 (6p) 로 추가
- **이유**: 부자(父子) 관계는 모자(母子) 관계와 본질적으로 다름 (편재 vs 정인)

### D8. 형제 관계 = 옵션 (미반영)
- **이유**: 운영 단에서 형제 사주 입력 폼 추가 시 검토. 현재는 보류.

## 시각화 결정

### D9. 동물 유형 — 일간×신강신약 = 20개
- **검토 옵션**:
  - (a) 일간 10개만
  - (b) 일간 × 신강/신약 = 20개 ✅
  - (c) 60갑자 압축 12개
- **선택**: (b)
- **이유**: 정밀도 + 부모 친근감. 강한 호랑이 vs 여린 사슴 등 양육 톤이 명확히 갈림

### D10. 동물 일러스트 — 손그린 SVG (이모지 X)
- **이유**: 브랜드 일관성, 색 톤 통일 (오행 컬러 매핑), 운영 시 디자이너 일러스트로 교체 용이
- **구현**: `lib/animal-icons.tsx` 600줄

### D11. 레이더 차트 둘 다 — 오행 5각 + 십성 10각
- **이유**: 한 페이지는 오행 본질, 한 페이지는 십성 분포. 정보 다층화

### D12. STS 6요인 매핑은 스킵
- **검토**: STS 6요인(활동성·조심성·긍정정서·부정정서·사회적민감성·의도적조절)을 사주에 매핑할지
- **결정**: 스킵 — 사주 본연의 5오행만
- **이유**: STS 매핑은 신뢰도 부여 효과는 있지만 우리 분석은 사주 정통으로 가는 게 맞음

### D13. 비주얼 + 텍스트 균형 (PART 2 재구성)
- **맥락**: 처음 PART 2 9페이지를 모두 시각화로만 채움 → 데이터 대시보드 같은 어색함
- **변경**: 각 페이지에 **도입 단락(Lead) + 비주얼 + 인사이트 블록(Insight)** 3단 구조
- **이유**: 잡지 레이아웃처럼 읽혀야 양육 매뉴얼 톤이 살아남

## 카피·톤 결정

### D14. 자녀 호칭 — "호민이" (받침+이)
- **검토**: (a) 이호민 (풀네임), (b) 호민 (이름만), (c) 호민이 (받침+이), (d) 자녀
- **선택**: **(c) 호민이**
- **이유**: 풀네임은 의료·법률 톤. 받침+이가 한국 양육 코칭 표준
- **자동 판정 규칙**: 받침 있는 이름 → "이" 추가. 받침 없으면 이름만. "이"로 끝나는 이름은 그대로.

### D15. 압축형 라벨 불릿 금지
- **맥락**: AI가 "X: 값" 형태 압축 불릿을 자주 생성 → 직관적 이해 어려움
- **결정**: 프롬프트에 명시적으로 금지 + 좋은 예/나쁜 예 함께 박음
- **예시**:
  - ❌ `일간(日干)의 결: 닮은 결 (比和)`
  - ✅ `**일간(日干)의 결**: 닮은 결 (비화·比和) — 두 사람이 같은 오행을 일간으로 가진 거울 같은 사이입니다. 굳이 설명하지 않아도 본능적으로 통하지만, 비슷한 자존심이 부딪히면 좀처럼 물러서지 않는 순간도 함께 따라옵니다.`

### D16. 사주 용어 첫 등장 시 풀이 강제
- **이유**: 부모가 명리학 모른다고 가정. "비화"라고만 쓰면 의미 전달 X
- **프롬프트 명시**: 첫 등장 시 즉석 한 줄 풀이 (예: `(같은 오행끼리)`, `(나를 살려주는)`)

### D17. "가족 인연의 결" 도입 섹션을 한 줄 요약으로
- **맥락**: 운영 사이트에서 사주팔자 표 아래 "가족 인연의 결" 압축 불릿이 직관적이지 않다는 피드백
- **결정**: 압축 불릿 빼고 두 사람의 결을 한 줄로 압축한 형태로 대체
- **결과**: 위에 사주팔자 표가 이미 있으니 결론만 한 줄로 깔끔하게

### D18. 오행 "창의" → "호기심"
- **맥락**: 운영 사이트 오행 키워드 점검 시 목 = "창의"는 명리학적으로 정확히는 식상 영역
- **결정**: 자녀 사이트라 "호기심" 으로 변경
- **이유**:
  - 정통 명리학적으로 목의 "외향 탐색·뻗어나감" 본질과 직접 매칭
  - 자녀 친화도 + 정통성 균형
  - 부모가 자녀를 떠올렸을 때 가장 와닿는 단어

### D19. 오행 한 줄 묘사 — 추상 → 직관 행동 묘사
- **맥락**: "곧게 뻗어 자라며 새 것을 향해 손을 뻗는 결" 같은 시적 묘사가 추상적
- **결정**: 부모가 읽으면 자녀 모습이 즉시 떠오르는 행동 동사 중심
- **변경 예**:
  - 목: "곧게 뻗어 자라며..." → **"새로운 것에 먼저 다가가 직접 해보고 싶어하는 결"**
  - 화: "환히 타올라..." → **"좋고 싫음을 솔직하게 드러내며 활기차게 표현하는 결"**

### D20. "다섯 가지 자연의 결" → "오행(五行)"
- **맥락**: 운영 사이트의 "결의 결" 같은 동어반복
- **결정**: 정식 명칭 "오행(五行)" 로 변경 + 한자(木·火·土·金·水) + 한글(목·화·토·금·수) + 비유(나무·불·흙·쇠·물) 3단 표기

## 비즈니스 모델 결정

### D21. 인연 사주 카테고리 — 5개 (연애·결혼 전문)
- **검토 옵션**:
  - (a) 운영 12개 모두 (친구·동료·아이돌 등 포함)
  - (b) 5개 연애 전문 (연인/배우자/전 연인/썸/짝사랑) ✅
  - (c) 6개 (전 배우자 추가)
- **선택**: (b) 5개
- **제외 이유**: 친구·동료·아이돌은 사주 풀이 깊이 약함 / 전 배우자는 비중 작음

### D22. 짝사랑 — 상대 생년월일 필수
- **맥락**: 생일 모를 때 일간만으로 풀이하면 2만원 가치 안 나옴
- **검토 옵션**:
  - (a) 가격 차등화 (2만원 / 9,900원)
  - (b) 짝사랑 빼기
  - (c) 썸으로 통합
  - (d) 콘텐츠 보강
  - (e) 생일 필수 강제 ✅
- **선택**: (e) — 진입 시 안내 박스로 정중히 차단
- **이유**: 모든 카테고리 균일 퀄리티 + 단순한 운영 + 정직한 가격

- **비즈니스 효과**: 시기 전환 시점에 자연스러운 재구매 유도
