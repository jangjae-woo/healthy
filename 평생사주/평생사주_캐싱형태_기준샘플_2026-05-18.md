# 평생사주 캐싱 형태 기준샘플

작성일: 2026-05-18
기준 샘플: sample-001
목적: 평생사주를 LLM 없이, 실제 사주 계산값에 맞춰 문장 단위 캐시로 조립하기 위한 기준 형태를 고정한다.

## 1. 이 문서의 의미

현재 만든 것은 최종 전체 캐시가 아니라, 앞으로 모든 장에 적용할 캐싱 방식의 기준샘플이다.

핵심은 다음과 같다.

- 화면 형식은 `index-jang.html`을 그대로 따른다.
- 내용은 사주마다 달라져야 한다.
- 문장은 가능한 한 한 문장 또는 한 카드 항목 단위로 쪼개서 캐싱한다.
- 캐시 문장은 반드시 실제 사주 인자와 연결되어야 한다.
- 사주에 맞지 않는 문장은 풍부해 보여도 사용하지 않는다.
- LLM 호출 없이 `calculated.json`의 엔진 계산값만으로 선택한다.

## 2. 입력으로 반드시 읽는 사주 인자

이 샘플은 아래 계산값을 기준으로 문장을 선택한다.

| 항목 | 값 |
|---|---|
| 일간 | 을 |
| 강한 오행 | 목 |
| 약한 오행 | 수 |
| 용신/보완 기운 | 수 |
| 신강신약 | 신약 |
| 우세 십성 | 비견 |

십성 분포:

```json
{
  "비견": 3,
  "편재": 2,
  "정관": 1,
  "상관": 1,
  "편관": 1
}
```

오행 분포:

```json
{
  "목": 2.4,
  "화": 0.7999999999999999,
  "토": 2.2,
  "금": 1.4,
  "수": 0
}
```

## 3. 캐시 단위 기준

앞으로 각 페이지는 아래처럼 분해한다.

| 화면 단위 | 캐시 단위 | 설명 |
|---|---|---|
| 장 제목 | 짧은 고정/조건형 문구 | 레이아웃 유지를 위해 길이 제한 |
| 요약 카드 | 항목 1개당 캐시 1개 | 333처럼 비지 않게 최소 개수 보장 |
| 본문 문단 | 문장 1개 또는 2문장 묶음 | 사주 인자별로 교체 가능해야 함 |
| 리스트 | li 1개당 캐시 1개 | 조건에 맞는 항목만 선택 |
| 대운/시기 | 실제 대운 시작 나이 사용 | 표준화 나이 사용 금지 |
| 주의/보완 문장 | 약한 오행, 용신, 충돌 인자 기준 | 사주와 맞지 않으면 제외 |

## 4. 333 -> 444 수정 기준

문제:

- 333 이미지처럼 `사람들이 보는 본인`, `본인만 아는 본인` 카드가 3줄만 들어가면 화면이 비어 보인다.
- 이 상태는 원본 `index-jang.html`의 밀도와 맞지 않는다.
- 카드 문장이 적으면 캐시한 티가 나고, 사주 풀이도 얕아 보인다.

수정 기준:

- 각 카드 항목은 최소 5개를 유지한다.
- 각 항목은 실제 사주 인자와 연결한다.
- 단순히 글자 수를 늘리지 말고, 겉으로 보이는 모습과 안쪽 성향을 분리한다.
- 같은 의미가 반복되지 않게 한다.

## 5. 기준샘플: 2장 나란 사람은?

### 사람들이 보는 본인

아래 5개 항목은 `강한 오행`, `우세 십성`, `신강신약`을 기준으로 선택된 카드 캐시다.

- 자기 기준이 분명함
- 독립적인 결
- 듣고 맞춰주는 분
- 쉽게 휘둘리지 않음
- 자라나는 힘이 은근히 드러남

### 본인만 아는 본인

아래 5개 항목은 `약한 오행`, `용신/보완 기운`, `우세 십성`을 기준으로 선택된 카드 캐시다.

- 내 색 내고 싶다 욕구
- 혼자 결정하고 싶은 결
- 수 기운이 필요
- 비교보다 자기 기준이 편함
- 생각을 깊게 모으는 힘을 보완해야 편함

## 6. 선택 규칙 예시

| 조건 | 겉 카드 예시 | 안 카드 예시 |
|---|---|---|
| 비견/겁재 우세 | 자기 기준이 분명함 | 내 색 내고 싶다 욕구 |
| 정인/편인 우세 | 차분하고 조용 | 혼자 시간이 꼭 필요 |
| 식신/상관 우세 | 표현력이 먼저 보임 | 창작·표현 욕구 강 |
| 정재/편재 우세 | 현실감 있어 보임 | 결과를 오래 계산함 |
| 정관/편관 우세 | 책임감 있어 보임 | 스스로를 자주 점검함 |
| 약한 오행 존재 | 보완 필요 문장 추가 | 용신/보완 기운 문장 추가 |

## 7. 앞으로 모든 장에 적용할 원칙

1. 먼저 원본 페이지의 모든 문장과 카드 항목을 페이지별로 분해한다.
2. 각 문장을 `사주 인자 조건`과 연결한다.
3. 조건이 없는 일반 문장은 레이아웃 연결 문장으로만 둔다.
4. 조건 문장은 같은 슬롯에 여러 후보를 만든다.
5. 렌더링 때 실제 `calculated.json`과 맞는 후보만 고른다.
6. 원본보다 짧아지는 구간은 카드/문단 단위 최소 개수를 둔다.
7. 원본보다 과하게 길어지는 구간은 페이지별 최대 문단 수를 둔다.
8. 마지막에는 샘플 4개 이상으로 서로 다른 사주가 서로 다르게 나오는지 검사한다.

## 8. 검증 기준

이 기준샘플은 아래 검증을 통과해야 한다.

- `사람들이 보는 본인`: 5개 항목
- `본인만 아는 본인`: 5개 항목
- 네 샘플 모두 같은 문장만 반복되지 않을 것
- 카드 항목이 실제 사주 인자와 연결될 것
- `index-jang.html`의 화면 형식과 밀도가 유지될 것
