# 평생사주 무LLM 결정론 캐시 계약

작성일: 2026-05-18

## 이해한 목표

LLM을 쓰지 않는다.  
`index-jang.html`의 형식, 페이지 흐름, 카드/차트/표 구조는 그대로 유지한다.  
내용은 사주마다 달라야 하며, 실제 엔진 계산값에서 나온 사주 인자를 문장 단위 캐시에 주입해 조립한다.

즉 목표는 아래와 같다.

```text
실제 엔진 계산값
→ 사주 인자 추출
→ 문장 단위 expression-pool 선택
→ 1~12페이지 전체 block 조립
→ index-jang.html과 같은 렌더 구조에 주입
```

## 중요한 기준

- HTML 전체를 캐싱하지 않는다.
- LLM 문단을 캐싱하지 않는다.
- page → section → paragraph → sentence/list item 단위까지 쪼갠다.
- 필요한 경우 사용자가 말한 1~12번보다 더 잘게 쪼갠다.
- 같은 사람은 같은 결과가 다시 나와야 하므로 랜덤이 아니라 `personKey` 해시로 문장 후보를 고른다.
- 다른 사주는 일간, 일지, 일주, 오행, 십성, 신강신약, 용신, 대운 조합이 달라서 문장이 다르게 조립된다.

## 12페이지 매핑

자세한 기계 계약은 `cache-schema/lifesaju-no-llm-page-map.v1.json`에 있다.

```text
1. p1 표지
2. p2 들어가며
3. p4 내 사주
4. p-naran 나란 사람은
5. p5 재물운

10. p13 건강운

12. p16 마지막 당부
```

## 2026-05-18 세분화 보강

문장 캐시를 더 잘게 쪼갰다. 특히 `p-naran`, `p5`, `p7`, `p9`, `p11`, `p13`은 문단 단위가 아니라 문장/리스트 항목 단위까지 내려간다.

다만 풍부함보다 정확성이 우선이다. 모든 sentence-pool 항목은 아래 조건을 가져야 한다.

```text
requiredFactors: 반드시 맞아야 하는 사주 인자
forbiddenFactors: 걸리면 선택 금지인 사주 인자
semanticGroup: 같은 의미 반복 방지용 그룹
sourceFields: 이 문장이 참조한 엔진 필드
```

예:

```json
{
  "id": "identity.ilgan.jeonghwa.smallFire",
  "requiredFactors": { "ilgan": "정" },
  "sentence": "일간 정화(丁)는 작은 불의 결입니다."
}
```

이 조건이 없으면 문장이 아무리 좋아도 pool에 넣지 않는다.
